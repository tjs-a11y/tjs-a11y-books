Crypto Trading Account Security Checklist: MFA, Withdrawals and Recovery

A trading plan is incomplete if someone else can access the account. Security is a set of layers: protect the email account that controls password resets, use strong authentication, restrict withdrawals, and keep recovery material away from everyday devices. No single setting makes an account invulnerable.

1. Secure the email account first

The email address attached to an exchange is often the recovery route for password resets and security alerts. Use a unique password stored in a reputable password manager, enable multifactor authentication (MFA), and review recovery phone numbers, forwarding rules and logged-in sessions. Remove old devices and third-party app permissions you no longer recognize.

Do not reuse the exchange password anywhere else. A breach at an unrelated website can otherwise become a route into the trading account.

2. Prefer stronger authentication

Where supported, use a passkey or hardware security key. An authenticator app is generally preferable to SMS-only codes when the service offers it, because phone-number takeover and message interception are possible. Save backup codes offline in a secure place. Never share a one-time code with someone claiming to be support.

Official background: CISA guidance on strong passwords and phishing-resistant MFA.

3. Tighten withdrawal controls

  • Enable withdrawal address allowlisting if available, and understand any waiting period for adding a new address.
  • Turn on withdrawal confirmations and security notifications.
  • Use a separate, carefully verified address for each network where appropriate.
  • Before sending, verify the network, destination address and memo/tag requirements independently.
  • Do not approve an unexpected API key, wallet connection or withdrawal request.

Address allowlists reduce some risks but do not protect against every compromise, including an attacker who controls the account and can alter settings after defeating safeguards.

4. Protect wallet recovery material

A self-custody wallet's recovery phrase or private key can control the assets. Never enter it into a website, chat, support ticket or form to “verify” a wallet. Do not store an unencrypted photo or cloud note of it. Use the wallet maker's official documentation to understand secure backups and recovery procedures. Anyone who obtains the phrase may be able to move the assets.

5. Review API keys and connected apps

Delete unused API keys. If a key is needed for reporting or automation, grant only the minimum permissions required and disable withdrawals unless there is a compelling, independently reviewed reason. Restrict IP access where supported, set an expiry or rotation schedule, and review account activity after any suspected exposure.

6. A 10-minute monthly review

  1. Check recent logins, devices and active sessions.
  2. Review email recovery settings and MFA.
  3. Confirm withdrawal allowlists and notification destinations.
  4. Revoke unknown API keys, app connections and wallet approvals.
  5. Check that backup material remains accessible to you but not exposed online.
  6. Record what changed and when, without writing secrets into the checklist.

What this checklist cannot guarantee

Exchange custody, platform insolvency, phishing, malware, SIM swaps, compromised devices and blockchain transaction errors are different risks. Account security controls cannot eliminate counterparty or market risk. Verify current features and policies directly with the service you use.
